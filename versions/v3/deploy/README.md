# Private cloud integration

This branch preserves the existing application and adds confirmed-email Supabase authentication and private persistence. The archived main and GitHub Pages deployment remain independently recoverable.

Apply deploy/001_private.sql and deploy/002_storage.sql to the same Supabase database, using a privileged server connection. Set DATABASE_URL to the Supabase transaction-pooler connection with sslmode=require. The backend uses short transactions, SET LOCAL role and owner/application RLS. Keep the private schema outside exposed API schemas.

Enable public email registration, require email confirmation, and keep anonymous sign-in disabled. Configure a working custom SMTP provider and the three app-scoped callback allowlists. Passwords require at least 10 characters with uppercase, lowercase and digits. coach_member is no longer an access requirement. Only server-controlled app_metadata.coach_admin=true grants guide administration; user_metadata never grants that authority. Existing accounts and records remain valid.

Configure DEEPSEEK_API_KEY, SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, SUPABASE_SECRET_KEY and DATABASE_URL in the server environment or the untracked ~/.config/ai-career-coach/cloud.env file. Publishable keys and legacy anon keys are accepted for the browser. Secret keys remain server-only. Rotate the DeepSeek credential previously disclosed in chat.

Private PDFs use the career-resumes-private bucket and an owner/application/project path. Browsers fetch documents through the authenticated backend. Existing anonymous browser records are not imported automatically into a member account.

Apply deploy/003_account_quota.sql before deploying this increment. Every actual model attempt reserves an account-level ledger entry under a database advisory lock. All three applications share ACCOUNT_DAILY_LIMIT=10 per confirmed user per Asia/Hong_Kong calendar day. There is no global daily request cap. Existing rows across versions remain counted. Duplicate request IDs/model-step ordinals are rejected before transmission. A transport-proven connection/pool failure is marked not_sent and releases its reservation; uncertain read/write failures, timeouts after possible transmission, provider errors and invalid outputs retain the charge. No automatic model retry occurs. A 402 response persists the billing block; AI_REQUESTS_ENABLED=false is an explicit administrator emergency switch, not a daily cap. Historical records and non-AI operations do not reserve calls. Quotas count attempts and are not a guaranteed monetary ceiling. Deleting business data preserves accounting entries.

V2 uses optimistic revisions to detect concurrent edits. The delete action waits for pending writes, requires two confirmations and reports deleted projects/PDFs. Failed Storage deletion keeps catalog records for retry. Other applications and members retain their records.

Local development requires Python 3.11+ and Node 22+. Install the backend requirements and frontend dependencies, build the frontend, then start the original FastAPI entry point. Build with the root base path for standalone local use. V1/V2 use backend/app/main.py, Claude uses server.py. The combined deployment in the V2 branch builds with /v1/, /v2/ and /claude/ base paths and mounts independent application namespaces in one process.
